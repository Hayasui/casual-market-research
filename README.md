# casual-tag-market-research

这项技能面向休闲游戏立项团队。它用 Sensor Tower 的收入与下载圈定头部游戏和新品，为每个游戏记录可追溯的题材与呈现标签，再汇总成一份可离线打开的单文件看板。

当前版本 **v0.1.5**，变更记录见 [更新说明](CHANGELOG.md)。

## 功能

- **品类范围**：合成（二合与三合合并统计）、三消、混变益智、模拟经营，共四类。试点档可只跑合成一类。
- **标签体系**：每个游戏取 2–3 个主标签，涵盖主题材（一级 › 二级）、呈现和融合。叙事类型与叙事强度单独记录。
- **可追溯**：每个标签绑定一条非买量证据（商店描述、实机截图、玩家评论或公开评测），证据来源与原文一并留档。画风依据写明所看的实机截图和画面区域。
- **质量门槛**：词表经收敛后由人签字；独立上下文盲测要求主题材与呈现一致率都达到 80% 以上，标签集合重叠率达到 75% 以上。
- **数据纪律**：市场和新品的收入、下载统一采用 Sensor Tower 双端合并数据。第三方资料用于补充描述、截图和发现新游线索。新品排序只使用 Sensor Tower 数据。

## 产出

| 产出 | 内容 |
|---|---|
| 市场盘面 | 四品类近六个完整自然月的收入、下载、环比与头部集中度 |
| 产品档案 | 头部十个游戏与运行日前滚动一年内首发新品的产品卡，含题材、呈现、融合标签与证据出处 |
| 供给差矩阵 | 主题材与呈现两个切面的密度与收入分布，附高频组合表 |
| 机会卡 | 全量档输出 3–5 张立项方向卡，含适配条件、反例与代价；试点档仅列判据占位 |
| 影视借鉴 | 试点档按高频现状标签挑 2 部；全量档按机会卡挑 6–8 部，附年份与完整剧情段落 |
| 看板 | 单文件 HTML，可离线打开与打印，另附分体版与图片目录 |

## 安装

```bash
git clone https://github.com/Hayasui/casual-market-research.git
```

克隆到本地技能目录即可，技能自带可执行脚本。

### 环境要求

- Python 3.11 或更高版本，仅用标准库。
- 可访问 Sensor Tower 的项目工作区；个人空间无法调用该数据源。
- 可选：第三方商店元数据通道，用于补齐英文描述与商店截图。
- 磁盘占用约 10 MB，另加看板图片。
- 当前工作目录需要可写；没有指定位置时，报告落在工作目录下的 reports 目录。

## 使用

在助手会话中可以直接提出需求。不熟悉这个技能的话，先读 [使用指南](GUIDE.md)，一页讲清怎么开口与中间会停在哪一步。

> 帮我做一份休闲品类题材供给差看板，先跑合成一类。

默认先跑合成试点。市场统计取近六个完整自然月。新品资格从上一年同日算到运行日，起止两天都算。运行日为 2 月 29 日时，从上一年 2 月 28 日算起。

开工时技能会先做一次本地环境自检：脚本与配置是否齐备、报告目录能否写入，有问题当场报出。报告默认写到当前工作目录下的 reports 目录，想放到其他地方，在需求里直接说明路径即可。

流程分为取数、打标、矩阵与机会卡、看板与归档四步。词表整理好后，流程会停一次，等你用对话文字确认或指出要改的词。确认后会继续打标、独立重测和生成看板。四个阶段收尾时会自动生成续跑状态卡与产物哈希清单（每份产物附校验值），会话中断后新开对话，从状态卡接着跑就行。

## 目录结构

```text
casual-tag-market-research/
├── SKILL.md                 技能说明与流程总览
├── configs/                 品类定义、词表约束、交付策略
├── references/              四个阶段的规则、提示词模板与数据源规范
├── scripts/                 取数、打标质检、图表、看板编译
└── assets/                  看板样式与静态模板
```

## 适用范围

适用于休闲品类的选题与供给判断：某个题材有多少人在做、做成什么样、哪一块还空着。

不适用于以下三类任务：单品类玩法机制与付费设计的竞品深挖、围绕指定影视或 IP 池的改编适配评级、文化或时代背景专题研究。这几类各有更合适的做法与数据源，换一套流程更顺手。
